# Personas — named agents of a project, for workflow steps and dispatch

> Status: proposed (2026-10-24), not built. Branch: `brutus`.
> Builds on: `packages/cezar/src/skills.ts` (discovery precedence, frontmatter), `workflows/types.ts`
> (a step's `runner`, `model`, `allowedTools`, `skill`), `2026-09-10-dispatch.md` (`cez task create
> --runner --model --tools`), `2026-07-29-agent-profiles.md` (accounts, which personas are not).
> Backlog item: "agents like `.claude/agents` — we create personas for the project".

## 1. Problem

"The reviewer is Opus with read-only tools and the review skill; the implementer is Codex with
the repo's conventions skill" is said again in every workflow step and every `cez task create`.
Claude Code has `.claude/agents/*.md` for this, but those files describe Claude's subagents:
one backend, Claude's tool names, invisible to Codex and OpenCode runs.

## 2. Decisions

| Question | Decision | Why |
| --- | --- | --- |
| Format | **cezar's own, `.ai/cezar/agents/<name>.md`** | Needs backend, cezar tool names, skills and a default workflow — more than Claude's frontmatter carries. |
| Where used | **Workflow steps (`agent: <persona>`) and dispatch children (`cez task create --as <persona>`)** | Not a composer picker (declined for now). |
| Claude's own files | Read-only awareness: a `.claude/agents` file is listed as "Claude-only" and usable as a persona on the Claude backend; nothing is rendered back | One source of truth. |

## 3. The file

```markdown
---
name: reviewer
description: Reads a branch against the base, writes findings, never edits.
runner: claude            # any RUNNER_IDS value; optional → project default
model: opus               # optional
allowedTools: [Read, Grep, Glob, Bash(git *)]   # optional; cezar's allowedTools grammar
skills: [code-review, repo-conventions]          # skill names from discovery
dispatch: { maxSubtasks: 0 }                      # optional defaults for children it may spawn
---
You are the project's reviewer. …                 # the system prompt body
```

Discovery: `.ai/cezar/agents/` (project, committable — the `.gitignore` allowlist), then
`~/.cezar/agents/` (global), then `.claude/agents/*.md` mapped (`tools` → `allowedTools`,
`model` kept, runner fixed to `claude`, marked `source: 'claude'`). Project wins by name.

## 4. Where it applies

- **Workflow step:** `agent: reviewer` on an agent step sets `runner`, `model`, `allowedTools`
  and prepends the persona body to the step's system prompt and its skills to the step's;
  explicit step fields override persona fields. `load.ts` validates the name exists at load
  time (an unknown persona is a `stepsIssue`, like a bad `onFail.retry`).
- **Dispatch:** `cez task create --as reviewer "<objective>"` fills the child's runner, model,
  tools and system prompt the same way; the engine's budget rules are unchanged. The parent's
  prompt lists the project's personas so an agent can choose one by name.
- **Cockpit:** Settings → project → **Agents** lists personas (name, description, runner,
  model, source), with an editor for the file (the Markdown editor Skills use) and a
  **New persona** form. The workflow editor's step form offers a persona picker.

## 5. Backend mapping

Claude: body as `--append-system-prompt`, tools as `allowedTools` (already honoured). Codex,
OpenCode, Cursor, Copilot, Junie, pi: body as the step's system prompt, model where the
backend takes one, tools ignored with the note the runner already emits for `allowedTools`
(AGENTS.md: only Claude honours them). Nothing persona-specific leaks past the runner seam.

## 6. API

```
GET  /agents                    → { personas: Persona[] }        (project-scoped, both mounts)
PUT  /agents/:name              { markdown }                      trusted operator
DELETE /agents/:name
```

Contract `agents.ts`: `personaSchema` with the frontmatter fields plus `source`.

## 7. Security

A persona is a system prompt and launch options committed in the repo — the same trust as a
skill or a workflow file. `allowedTools` can only narrow what the project already allows.

## 8. Zero config

No personas → nothing changes anywhere. `.claude/agents` files are read, never written.

## 9. Not done here

- A persona picker in `/new` and in the chat (declined for now).
- Rendering personas to `.claude/agents`.
- Per-persona accounts (agent profiles are a different axis).
