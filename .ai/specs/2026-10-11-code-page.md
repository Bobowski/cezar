> `code-state.ts`).
> As built, where it differs from the text below:
> - **One editor group.** The second group (split) is not built.
> - **File operations are toolbar buttons** (new, rename, delete for the active file), not a tree
>   context menu; folders appear by creating a file inside them (git tracks no empty directory).
> - **Rendered views**: an image opens as an image; Markdown opens as text only.
> - **Layout and drafts live in `localStorage`** (`cez:code:layout:…`, `cez:code:draft:…`), keyed
>   by project and checkout — not in the workspace UI state. A draft typed against an older
>   version of a file comes back with the conflict banner.
> - **Compare** shows the file as it is on disk beside the buffer, read-only — not a diff.
> - **The change bell** (`GET /repo/watch`) watches on macOS and Windows only: a recursive watch
>   on Linux is one inotify handle per directory. There the page revalidates on window focus and
>   on a refused save, which is the floor everywhere.
> - **Delete** asks once and says whether git still holds the file; the server answers with the
>   blob id of the deleted bytes. It does not show the diff first.
> - **Keyboard**: the shortcuts are live on the page; the keyboard settings section is still
>   hidden, so nothing is registered there.
> - **Search** adds nothing to §5; `Ctrl/Cmd+Shift+P` (command palette) is not bound — the
>   cockpit's own palette is `Ctrl/Cmd+K`.

## 1. Problem

To write a function by hand the user opens VS Code. cezar has two file surfaces and neither is an
editor: the task's Files column is a viewer with an Edit switch per file, and `/git/files` is
read-only by design. Both are right for what they are — inspecting what an agent did — and wrong
for writing code: one file at a time, no tabs, no search across files, no terminal beside it, and
the main checkout cannot be written at all.

## 2. Decisions taken with the owner (2026-10-11)

| Question | Decision |
| --- | --- |
| Which checkout? | **The main checkout by default, with a switcher to any task's worktree.** The task workspace's Files column is not changed. |
| Saving | **Explicit, `Ctrl+S`.** Dirty marker on the tab, a warning before a dirty tab or the page closes. No autosave. |
| Language intelligence (LSP) | **Out of this spec.** §9 lists what must not be built in a way that blocks it. |
| Navigation | **A new `Code` item beside `Git`.** The Git page and its URLs are untouched. |

## 3. The page

`/p/:projectId/code` and `/p/:projectId/code/*` (the splat is the active file's path, as
`/git/files/*` does). `?tree=<runId>` selects a task's worktree; absent means the main checkout.

```
┌ checkout switcher ─ tabs ───────────────────────────────┬─ Preview ─┐
│ tree        │ editor (one or two groups, split vertical) │ (optional)│
│ + filter    │                                            │           │
│             ├────────────────────────────────────────────┤           │
│             │ bottom panel: Terminal · Services · Search │           │
└─────────────┴────────────────────────────────────────────┴───────────┘
```

- **Tree** — the whole path index in one response, filter box, change marks (`M`/`A`/`U`) from
  `/repo/changes`. Context menu: new file, new folder, rename, delete.
- **Editor** — `code-mirror-editor.tsx`, always editable; no view/edit switch. Tabs with preview
  semantics (single click reuses an italic tab, double click or an edit keeps it). Up to two editor
  groups. Markdown and images keep their rendered view behind a per-tab toggle.
- **Bottom panel** — Terminal tabs owned by the project (services spec §5), the Services dock, and
  content-search results.
- **Preview** — the task workspace's `browser-view.tsx`, unchanged, as an optional column.
- **Layout state** (open tabs, active tab, split, panel sizes) persists per project and per
  checkout through the existing workspace UI state; unsaved buffers are kept in `localStorage`
  drafts keyed by path + base hash so a reload does not lose typing.

## 4. Saving and the other writer

An agent may be writing the same checkout. The guard is the one file editing already uses:

- Every read returns `hash`; every save sends it as `baseHash`. A mismatch is `409 conflict` and
  nothing is written.
- On conflict the tab shows a banner with three choices: **Compare** (disk vs. buffer in the diff
  component), **Reload from disk** (drops the buffer), **Overwrite** (re-sends with the fresh
  hash). Never a silent choice.
- A clean tab whose file changed on disk reloads itself. A dirty tab gets the banner without
  waiting for a save.
- Change detection: a `code:<projectId>:<tree>` WebSocket topic publishing a bare version counter
  from a debounced `fs.watch` on the checkout. Demand-driven — the watcher exists only while a
  Code page is open — and the bus carries no path or content; the client re-fetches hashes of its
  open tabs over HTTP. Where recursive watch is unavailable, hashes are revalidated on window
  focus and on save, which is the floor either way.

## 5. API (contract first; chained into the existing `/repo` family and the run file family)

| Route | Purpose |
| --- | --- |
| `GET /repo/tree`, `GET /repo/files` | exist |
| `PUT /repo/files` | save: `{ path, content, baseHash }` → `{ hash }`, via `writeWorktreeFile` |
| `POST /repo/files` | create a file or folder; refuses an existing path |
| `POST /repo/files/rename`, `DELETE /repo/files` | twins of the run routes |
| `GET /repo/search?q=&regex=&case=&glob=` | content search |
| `GET /runs/:id/tree`, `GET /runs/:id/search` | the same two for a task worktree (file read/write/rename/delete already exist there) |
| `GET/POST /repo/terminal…` | project-owned terminal sessions (services spec §5) |

**Content search** is `git grep -n -I --untracked` in the checkout, so it sees exactly the index
plus untracked-not-ignored files — the same set the tree shows. Bounds: 2 000 matches, 200 per
file, 250-character lines, 5 s wall clock, killed when the request aborts; an over-limit answer
says `truncated: true`. Fixed-string by default; the pattern is always passed after `-e`, never
interpolated into a shell.

## 6. Writing the main checkout — what the old refusal was load-bearing for

`/repo/files` answers `editable: false` today, and the file-editing spec refused repo-level writes
because "the repo checkout is the user's real working tree, with no worktree isolation to fall
back on". That refusal protected three things. Each needs a named replacement:

| The refusal guaranteed | Replacement |
| --- | --- |
| A cockpit client could never change code the user runs outside cezar. | Writes follow the existing **`fileEdit` capability** unchanged: on for a local cockpit, off for a hosted one unless `CEZ_FILE_EDIT=1`. No new flag. `.env.example` and `docs/reference.md` say `CEZ_FILE_EDIT` now covers the main checkout. |
| An ignored file (`.env`) was unreachable — read or write. | The index-membership guard stays on every read and applies to writes: the target must be in the index, or be a NEW path that `git check-ignore` does not match. One error wording for ignored and missing, as today. `.git/` is refused outright. |
| A mistaken write had a recovery path (a task worktree can be thrown away). | Saves are whole-file with `baseHash`; delete moves nothing to a trash, so **delete and rename of a tracked file require the file to be clean or confirm with the diff shown**, and git is the undo. Untracked files get a plain confirm that says they cannot be recovered. |

`repoBrowserEditRefusal()` becomes the `fileEdit` refusal; `/git/files` stays a viewer by not
rendering the save affordance, not by a second policy.

## 7. Hosted and narrow screens

- `fileEdit` off: the page opens read-only with the reason in the status bar; search, quick open
  and tabs all work.
- `terminal` off: the bottom panel shows Search only.
- Below the tablet breakpoint: one pane at a time (tree → editor → panel), no split, Preview as a
  full-screen sheet. Usable for a quick fix, not designed as the primary editing surface.

## 8. Phases

1. **Editor** — route, checkout switcher, tree with filter, tabs, save + conflict banner,
   create/rename/delete, quick open, layout persistence, repo write routes and their guards.
2. **Panel** — project terminal, Services dock, content search, Preview column.
3. **Working with git and agents** — change gutter against `HEAD`, a compact "changed files" list
   that links to the Git page for staging and commit, and **Ask about selection**: the selected
   range becomes a chip on a new or existing task's next message (file, lines, text), the same
   mechanism as Design Mode picks.

Each phase is usable on its own; phase 1 already removes the VS Code round trip for a small edit.

## 9. Not in scope

LSP (definition, references, live type errors), debugger, extensions, multi-cursor refactors beyond
what CodeMirror ships, editing ignored files, a merge-conflict editor, replacing the task
workspace's Files column.

To keep LSP possible later: the editor's document identity is `(tree, path)` and every buffer
change already flows through one CodeMirror update listener — a language client can attach there
without a rewrite. Nothing else is prepared on purpose.

## 10. Defaults applied without asking (override before implementation)

| Question | Default | Why |
| --- | --- | --- |
| Can ignored files (`.env`) be edited here? | No. | Keeps the one guarantee `/repo/files` documents. Env files are edited in Settings → Environment (spec `2026-10-12-project-env-files`). |
| Search-and-replace across files? | Not in v1; in-file replace only. | A multi-file write with per-file `baseHash` is its own failure surface. |
| Staging and commit inside Code? | No — link to the Git page. | The owner kept Git as its own page; two commit UIs would drift. |
| Format on save? | No. | Needs the project's formatter and a config decision; run it in the terminal. |

## 11. Verification

- Server: `PUT/POST/DELETE /repo/files` — conflict, ignored target, `.git`, traversal, symlink,
  hosted refusal; `fs-browse-privacy`-style case proving an ignored `.env` is neither readable nor
  writable nor reported by search. Search bounds and abort.
- A guard test that passes before and after: `/git/files` still offers no save.
- Contract parity, route parity, typed bodies, BC inventory.
- Web: tab/dirty state, conflict banner's three exits, draft restore after reload, key bindings.
- E2E (dry run): open a file, edit, `Ctrl+S`, see it in `/git` changes; change it on disk under a
  dirty tab and see the banner.
